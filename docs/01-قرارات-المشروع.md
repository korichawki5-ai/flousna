### ⚠️ قرار معماري حاسم: لقطة سعر الصرف (Rate Snapshot)
```sql
amount        NUMERIC(14,2)  -- المبلغ بالعملة الأصلية (مثلاً 100.00)
currency      CHAR(3)        -- 'EUR'
rate_to_dzd   NUMERIC(12,4)  -- سعر الصرف لحظة التسجيل (مثلاً 235.0000)
amount_dzd    NUMERIC(14,2)  -- 23500.00 ← لقطة محفوظة
```
**السبب:** لو حُوّل بالسعر الحالي دائماً، فإن تقرير يناير سيتغير كلما حُدّث السعر — **خطأ فادح في تطبيق مالي**.
باللقطة، **التقارير التاريخية تبقى ثابتة وصحيحة للأبد**.

**النتيجة:** كل التقارير والميزانيات تُجمع بـ **دج** (عملة الأساس)، مع عرض تفصيلي لكل عملة.

### 🎁 ميزة جزائرية إضافية: سعران للصرف
- **السعر البنكي الرسمي** (Bank of Algeria)
- **سعر السوق الموازية** («السكوار» / Square Port Said) ← الذي يهمّ الناس فعلياً

### قواعد تقنية إلزامية
```
❌ ممنوع FLOAT / DOUBLE للمبالغ إطلاقاً
   (يسبب: 0.1 + 0.2 = 0.30000000000000004)
✅ NUMERIC(14,2) في PostgreSQL
✅ العمليات الحسابية بأعداد صحيحة (سنتيمات) حيث يلزم
✅ العرض فقط يُقرّب — التخزين والحساب بدقة كاملة
✅ Intl.numberFormat(locale, currency:) — لا تنسيق يدوي أبداً
✅ الأرقام السالبة: لون أحمر + أيقونة ▼ (لا الاعتماد على اللون وحده — Accessibility)
✅ محاذاة الجداول: end (تنقلب تلقائياً) لا right
```

### حدود معروفة
1. السعر يدوي = **مسؤولية المستخدم** — سيظهر تنبيه: «أسعار الصرف تُدخل يدوياً. التطبيق لا يوفّر أسعاراً رسمية.»
2. **لا نصائح استثمارية أو صرفية أبداً** (حماية قانونية)
3. تسجيل عملات أجنبية لأغراض شخصية = **تتبع فقط، لا وساطة مالية** → خارج نطاق ترخيص PSP ✅

## 6️⃣ Offline-first (قرار المطوّر بالتفويض)

> **قرار:** **Offline-first + مزامنة اختيارية**

### لماذا (تحليل الواقع الجزائري)
- 📶 إنترنت موبايل متقطع، مناطق بيضاء، باقات محدودة
- 🛒 المستخدم يسجّل مصروفه **لحظة الشراء** — في السوق، في الطاكسي، عند الحانوت
- ❌ **إن فشل التسجيل، يفقد الثقة ويهجر التطبيق للأبد**
- 🚀 «جرّب بدون حساب» يقلل الاحتكاك ويزيد التحويل بشكل كبير

### المعمارية
```
[الواجهة Flutter]
      ↓
[Riverpod Repository]
      ↓
[Drift / SQLite محلي]  ← مصدر الحقيقة الوحيد (Source of Truth)
      ↓
[طابور المزامنة Sync Queue]  ← يعمل في الخلفية عند توفر الإنترنت
      ↓
[Supabase PostgreSQL]  ← نسخ احتياطي + تعدد الأجهزة
```

### قواعد المزامنة
| القاعدة | التنفيذ |
|---|---|
| مصدر الحقيقة | **القاعدة المحلية دائماً** — الواجهة تقرأ منها فقط |
| التعارضات | **Last-Write-Wins + سجل تعديلات محفوظ** (لا يُفقد شيء أبداً) |
| المعرّفات | **UUID v4** يولَّد محلياً (لا انتظار للسيرفر) |
| الحذف | **Soft delete** + `deleted_at` (حتى لا يعود السجل بعد المزامنة) |
| الفشل | طابور صبور + إعادة محاولة exponential backoff + مؤشر حالة واضح للمستخدم |
| بلا حساب | يعمل كاملاً · وعند التسجيل تُرفع البيانات المحلية تلقائياً |

### حدّ معروف بصدق
> تعارضات المزامنة (نفس العملية عُدّلت من جهازين) **لا يوجد لها حل سحري**.
> القاعدة المطبّقة: **Last-Write-Wins مع سجل تعديلات محفوظ** — لا يُفقد شيء، لكن النسخة الظاهرة هي الأحدث.
> هذا **معيار الصناعة** (يستعمله Google Keep و Notion).

```
1. المستخدم يضغط «الترقية إلى Pro» → يختار الخطة
2. التطبيق يولّد «رمز تفعيل» فريد (8 محارف، مشفّر، مرتبط بـ user_id، يُستخدم مرة واحدة)
3. يُفتح واتساب عبر رابط wa.me مع رسالة معبّأة مسبقاً:
   ┌────────────────────────────────────────┐
   │ 🔔 طلب تفعيل فلوسنا Pro                │
   │ الرمز: FL-7K3M-9QXR                    │
   │ الخطة: سنوي — 2.500 دج                 │
   │ الطريقة: BaridiMob / CCP               │
   │                                        │
   │ بيانات التحويل:                        │
   │ CCP: XXXXXXXXX XX                       │
   │ الاسم: [اسمك]                           │
   │                                        │
   │ بعد التحويل أرسل:                       │
   │ • صورة الوصل                            │
   │ • رقم العملية (Réf) من BaridiMob        │
   └────────────────────────────────────────┘
4. المستخدم يحوّل عبر BaridiMob / CCP → يرسل صورة الوصل + رقم العملية
5. أنت تتحقق في تطبيق BaridiMob من رقم العملية (مرجع فريد — لا يمكن تزييفه)
6. في لوحة الإدارة: تبحث عن الرمز → تضغط «تفعيل»
7. **Edge Function** تحدّث حالة الاشتراك في PostgreSQL (بمفتاح Service Role — على السيرفر فقط)
8. التطبيق يستقبل التغيير عبر Realtime → تظهر رسالة «🎉 تم تفعيل Pro — شكراً لك!»
9. يُرسل إيصال PDF للمستخدم (سجلّ تجاري/قانوني)
```

### 🛡️ الحماية من الاحتيال (إلزامي)
| الخطر | الحماية |
|---|---|
| وصل مزوّر (Photoshop) | **التحقق من رقم العملية في BaridiMob** — مرجع فريد لا يُختلق |
| مشاركة رمز التفعيل | الرمز **مرتبط بـ user_id** ومستخدم **مرة واحدة** فقط |
| توليد رموز عشوائي (بوت) | **Rate limiting**: 3 طلبات / ساعة / مستخدم |
| إعادة استخدام رمز قديم | عمود `used_at` + تحقق في Edge Function |
| تلاعب بالاشتراك من الواجهة | **RLS على جدول subscriptions** + كل التفعيل عبر Edge Function فقط |
| نزاع لاحق | **سجل تدقيق (audit log)** لكل عملية تفعيل: من، متى، المرجع، المبلغ |

### ⚖️ الوضع القانوني (صادق)
- ✅ **التطبيق أداة تتبع يدوي فقط** — لا محفظة، لا تحويل أموال، لا ربط بنكي → **خارج نطاق ترخيص PSP** (بنك الجزائر)
- ✅ **الدفع يحدث خارج التطبيق كلياً** (BaridiMob/CCP) → التطبيق لا يعالج أي بيانات دفع → **لا ينطبق PCI-DSS**
- ✅ **التفعيل اليدوي = بيع ترخيص برنامج**، وليس وساطة مالية
- ⚠️ **مع ذلك:** استشر محامياً متخصصاً قبل الإطلاق التجاري (كما ذكرت أنت) — هذا ليس بديلاً عن الاستشارة القانونية
- ⚠️ **لا تقدم أبداً** استشارات ضريبية أو قانونية أو استثمارية داخل التطبيق

### حدود معروفة بصدق
1. **التفعيل اليدوي لا يتوسع** — عملي حتى ~50 عملية/يوم. بعدها ستحتاج Satim/CIB أو Google Play Billing
2. **زمن الاستجابة:** المستخدم قد ينتظر ساعات حتى تفعيله → سأضيف شاشة «طلبك قيد المعالجة» واضحة + **تفعيل تجريبي فوري 24 ساعة** لتجربة Pro قبل الدفع ⭐
3. **واتساب قد يقيّد** الحسابات التي ترسل رسائل جماعية آلية — **لن نفعل ذلك** (المستخدم هو من يراسل أولاً دائماً)
4. **لا إيصال ضريبي رسمي آلي** — الإيصال PDF من التطبيق هو سجل تجاري، لا وثيقة ضريبية

### استضافة البيانات — الصدق الكامل

|---|---|

**إجراءات التخفيف المعتمدة:**
1. **إفصاح صريح** في سياسة الخصوصية: «تُستضاف بياناتك على خوادم Supabase في فرانكفورت (ألمانيا) ضمن الاتحاد الأوروبي، المحمي بـ GDPR»

5. **حق التصدير والحذف الفوري** بأي وقت
6. **RLS** = حتى لو اختُرقت المفاتيح، لا وصول لبيانات مستخدم آخر

> ⚠️ **لا أدّعي الامتثال 100%.** هذا **حدّ معروف** وسأصرّح به دائماً.
> **التوصية الصادقة:** استشر محامياً متخصصاً في القانون الرقمي الجزائري قبل الإطلاق التجاري.
