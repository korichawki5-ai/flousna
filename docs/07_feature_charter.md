## المبادئ الحاكمة (لا تتغير)

1. **أداة تتبع يدوي فقط**: لا محفظة، لا تحويلات حقيقية، لا ربط بنوك، لا أسماء مؤسسات في أي شاشة.
   «الادخار التلقائي» و«التوزيع الذكي» عمليات **افتراضية داخل سجلات التطبيق** (قيود محاسبية محلية) وليست حركة أموال حقيقية.
2. **شفافية بلا صناديق سوداء**: كل «ذكاء» قاعدة حسابية مفسّرة بالعربية يرى المستخدم معادلتها (لا ادعاءات AI).
3. **العائلة أولاً على جهاز واحد**: الملفات الشخصية (Profiles) محلية في المرحلة 2؛ تعدد الأجهزة يأتي مع المزامنة (م3) وضمن حدود الباقة (1/2/3 أجهزة).
4. **كل مبلغ عدد صحيح بالسنتيم** — «تتبع كل قرش» حرفياً.
5. خصوصية: قانون 18-07 المعدّل؛ الحد الأدنى من البيانات؛ موافقة صريحة مسبقة.

## تقسيم المرحلة 2 (دفعات مُختبَرة على جهاز المستخدم قبل التالية)

- **م2.1 — القلب**: ✅ **منجزة** — drift + الجداول (transactions, custom_categories, profiles أساس) + الحفظ الحقيقي + الملخص الحقيقي + البحث + فئات مخصصة + تحديث تلقائي للشاشات.
- **م2.2 — الالتزام**: 🟡 **جزؤها الأول منجز** (السقوف وأشرطة التقدّم + التنبيه داخل التطبيق). الباقي: الأهداف + الادخار بالاقتراح + الديون (عليك/لك) + المتكررات والالتزامات الثابتة.
- **م2.3 — العائلة**: الملفات الشخصية المحلية + حدود الأفراد + ملخص العائلة + الأهداف المشتركة.

ثم م3 مزامنة ← م4 لوحة تحكم وتفعيل ← م5 تقارير وذكاء وموسميات ← م6 توقيع وتثبيت.

## سجل القرارات (تحديث 22/09/2026 — اعتماد المستخدم)

1. **الادخار التلقائي = اقتراح بزر تأكيد**: عند تسجيل دخل يعرض التطبيق بطاقة
   «خصم X٪ للهدف؟» بزراً واحد للتنفيذ — لا خصم صامت أبداً. (م2.2)
2. **العائلة محلية أولاً**: م2.3 على جهاز واحد؛ تعدد الأجهزة مع مزامنة م3 ضمن حدود الباقة.
3. **اعتماد الخطة وبدء م2.1 فوراً**: drift + الحفظ الحقيقي + الفئات المخصصة + البحث + الملخص الحقيقي.

### قرارات تقنية مُلزمة أُضيفت أثناء التنفيذ (22/09/2026)

4. **التحديث التلقائي بلا اعتماد على ذاكرة المبرمج**: لا يُبطَل مزوّد يدوياً بعد كل كتابة
   (يُنسى في مسار واحد فيظهر «رصيد قديم» — أسوأ عطل في تطبيق مالي). بدلاً منه عدّاد واحد
   `dbRevisionProvider` يراقب كتابات drift (`tableUpdates`) ويرتفع عند أي INSERT/UPDATE/DELETE،
   فتقرأ كل الشاشات من جديد. النتيجة: أي مسار كتابة مستقبلي (استيراد نسخة، مزامنة م3، صيانة)
   يُحدّث الواجهة تلقائياً بلا كود إضافي. محروس باختبار `test/add_flow_test.dart` أثبتنا أنه
   **يفشل** عند تعطيل المراقبة — لا اختبار فارغ.
5. **التنبيه = قاعدة صريحة لا تقدير**: حالة السقف تُحسب بمعادلة منشورة للمستخدم
   (النسبة = المصروف ÷ السقف × 100 · بلوغ 100٪ = حالة حرجة بلا «تجاوز بـ 0 دج»)،
   والتنبيه لا يظهر إن لم يكن هناك ما يستحق التنبيه («لا تنبيه بلا سبب» يمنع
   تعليم المستخدم تجاهل التنبيهات).
6. **الهجرة تُختبَر على قاعدة إصدار 1 حقيقية**: أي ترقية مخطط تُثبت باختبار يبني
   قاعدة النسخة السابقة بحركات فعلية ثم يفتحها بالنسخة الجديدة — «صفر فقدان بيانات»
   قاعدة مُختبرة لا وعد.
7. **البوابة `audit_lint` تحترم `exclude` من analysis_options.yaml** (الملفات المولّدة ليست مخالفات)،
   وصارت تفهم الأقواس الزاوية للنوع العام (`FutureBuilder<Result<X, Y>>`) فلا تُحصي فواصلها
   فواصلَ وسائط. مُثبَّت بحالتين في `tool/audit_lint_selftest.py` — «اختبر الفاحص قبل أن تثق به».
8. **بوابة الترجمة تفهم ICU فعلاً**: كانت تعتبر «و» و«et» متغيّرات فترفض ترجمات
   عربية وفرنسية سليمة؛ أُبدلت بتعبير نمطي بمحلّل أقواس حقيقي، مع
   `tool/check_l10n_selftest.py` يثبّت ألا إنذار كاذب وأن الأعطال الحقيقية تُكتشف.
