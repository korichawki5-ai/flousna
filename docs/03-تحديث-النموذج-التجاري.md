# 2️⃣ النموذج التجاري الجديد: تجربة 7 أيام → باقات مدفوعة

## التغيير الجوهري

| | النموذج القديم (Freemium) | **النموذج الجديد (Trial → Paid)** ⭐ |
|---|---|---|
| المجاني | نسخة محدودة **للأبد** | **لا يوجد** — تجربة 7 أيام فقط |
| الدفع | اختياري | **إلزامي بعد التجربة** |
| الإيراد | بطيء (2–5% تحويل نموذجي) | **أسرع وأعلى** |
| الانتشار | 🟢 واسع (مجاني = انتشار فيروسي) | 🔴 **أبطأ** (لا مجاني = لا توصيات) |
| قاعدة المستخدمين | كبيرة | أصغر لكن **مدفوعة** |

## ⚠️ تحذير صريح (لا مجاملة)

**إزالة النسخة المجانية تماماً لها ثمن حقيقي:**
- 🔴 **الانتشار الفيروسي يموت.** في الجزائر، التطبيقات تنتشر لأن «واحد قال لواحد جربها، مجانية». بدون مجاني، كل مستخدم جديد = **جهد تسويقي مدفوع أو شخصي**.
- 🔴 **معدل التحويل من التجربة نموذجياً 5–20%** — أي من 100 تنزيل، قد تدفع 5–20 شخصاً فقط.
- 🟢 **لكن:** من يدفع = **مستخدم جاد**، ودعمه أسهل، وإيراده مضمون.
- 💡 **توصيتي للتعويض:** فترة تجربة **7 أيام كاملة بوظائف Pro غير مقفلة** (لا نسخة مشوّهة) — هذه **أقوى أداة إقناع**، لأن المستخدم يعيش القيمة الحقيقية ثم يخاف فقدانها.

## 📦 الباقات الثلاث

### الهيكل المقترح

| | 👤 **الفرد** | 👥 **زوجان** | 👨‍👩‍👧‍👦 **العائلة** |
|---|---|---|---|
| **لمن** | شخص واحد | اثنان يتشاركان الميزانية | عائلة كاملة |
| **الملفات الشخصية** | 1 | 2 | حتى 6 |
| **الأجهزة** | 1 | 2 | 3 |
| **كل وظائف Pro** | ✅ | ✅ | ✅ |
| **ميزانية مشتركة** | — | ✅ | ✅ |
| **تقرير موحّد للأسرة** | — | ✅ | ✅ |
| **مقارنة الإنفاق بين الأفراد** | — | — | ✅ |

### ⚠️ قرار تقني حاسم: كيف ننفّذ «زوجان» و«العائلة»؟

هناك **طريقان**، والفرق في الكلفة ضخم:

#### 🟢 الطريق أ: ملفات محلية (Profiles) — **توصيتي القوية للـ MVP**
```
الجهاز الواحد يحتوي حتى 6 ملفات شخصية
كل ملف = دفتر حسابات منفصل (فئات، ميزانية، حركات، أهداف)
مجموع الأسرة = تجميع محلي للملفات
الباقة تتحكم في «عدد الملفات المسموح» (1 / 2 / 6)
```
| المزايا | القيود |
|---|---|
| ✅ يعمل **Offline تماماً** — لا إنترنت ولا حساب مطلوب | 🔴 لا مشاركة بين جهازين |
| ✅ **RLS بسيط جداً** — لا تعقيد أمني | 🔴 «زوجان» = جهاز واحد مشترك |
| ✅ بناء سريع (~أسبوع) | 🔴 لا مزامنة بين هاتف الزوجين |
| ✅ يناسب الواقع الجزائري (جهاز الأسرة المشترك شائع) | |

#### 🔴 الطريق ب: حساب سحابي مشترك (Cloud Sharing)
```
دعوات عبر البريد · أدوار (مالك/عضو) · RLS متعدد المستويات
كل عضو على جهازه الخاص · مزامنة لحظية
```
| المزايا | القيود |
|---|---|
| ✅ كل فرد على جهازه | 🔴 **+4 أسابيع بناء** |
| ✅ مشاركة حقيقية | 🔴 **RLS معقّد = سطح أخطر للاختراق** |
| ✅ احترافي أكثر | 🔴 يتطلب حساباً وإنترنت للجميع |

> **⭐ توصيتي الصريحة:** **الطريق أ في MVP** (ملفات محلية) — ثم **الطريق ب في الإصدار 2.0** إن طلبه المستخدمون فعلاً.
> **السبب:** الطريق ب يضيف **4 أسابيع + خطراً أمنياً حقيقياً** لميزة قد لا يستخدمها أحد في البداية.
> **مهم:** سنذكر بوضوح في صفحة الأسعار أن «زوجان والعائلة = ملفات على نفس الجهاز»، **حتى لا يشعر المستخدم أنه خُدع**.

## 💰 التسعير — 3 سيناريوهات (القرار التجاري لك)

### التحليل الاقتصادي
> في الجزائر: **اشتراك نتفليكس ≈ 1.200 دج/شهر** · **قهوة ≈ 50–100 دج** · **متوسط الراتب ≈ 40.000–60.000 دج**
> التطبيق الذي «يوفّر لك 5.000 دج شهرياً» يبرّر سعره بسهولة — **لكن فقط إن كان السعر أقل من التوفير المُتوقَّع**.

### السيناريوهات

| | 🟢 **أ: اختراق السوق** | ⭐ **ب: متوازن** (توصيتي) | 🔵 **ج: مرتفع/احترافي** |
|---|---|---|---|
| **الفرد — شهري** | 200 دج | **300 دج** | 500 دج |
| **الفرد — سنوي** | 1.800 دج | **2.500 دج** | 4.500 دج |
| **زوجان — سنوي** | 2.700 دج | **3.900 دج** | 6.900 دج |
| **العائلة — سنوي** | 3.600 دج | **5.500 دج** | 9.500 دج |
| **من يصلح له** | بناء قاعدة مستخدمين سريعة | **التوازن الأمثل** | سوق ناضج + قيمة مثبتة |
| **الخطر** | 🔴 يُنظر إليه كـ«رخيص/غير جاد» | 🟢 منخفض | 🔴 يقتل التحويل بدون مجاني |

### 🎯 قاعدة التسعير النفسي المعتمدة (مهما اخترت)
1. **الأسعار السنوية = الافتراضية المعروضة** (تُظهر الشهري بخط أصغر)
2. **«وفّر 30%»** يظهر بوضوح على السنوي
3. **باقة العائلة = المرساة السعرية (Price Anchor)** — وجودها يجعل «الفرد» يبدو رخيصاً ⭐
4. **الترتيب البصري:** العائلة (يمين/الأبرز) ← زوجان ← الفرد — **لا تجعل الأرخص أولاً**
5. **لا أسعار بـ ,99** (مثل 299) — في السياق الجزائري **الأرقام المستديرة توحي بالثقة** أكثر

## 🔐 تنفيذ التجربة المجانية — المشكلة التقنية الصعبة

### ⚠️ التحدي الحقيقي (ولن أخفيه عنك)

> **كيف تمنع مستخدماً من إعادة تثبيت التطبيق للحصول على تجربة جديدة بلا نهاية؟**
> هذه **أصعب مشكلة** في أي نظام تجريبي، و**لا يوجد لها حل مثالي** — خاصة مع تطبيق Offline-first يعمل بلا حساب.

### الحل المتدرج المعتمد (3 طبقات)

#### الطبقة 1 — بلا حساب (مستخدم مجهول)
```dart
// في قاعدة SQLite المحلية، جدول مشفّر:
trial_started_at      // تاريخ أول تشغيل — يولَّد محلياً
trial_expires_at      // + 7 أيام
device_install_id     // UUID عشوائي فريد لهذا التثبيت
highest_seen_ts       // ⭐ أعلى طابع زمني شوهد ever (لمنع التلاعب بالساعة)
clock_tamper_flag     // علم إن انخفض الوقت عن highest_seen_ts
```
**مقاومة التلاعب:**
| الحيلة | الحماية |
|---|---|
| تغيير ساعة الجهاز للوراء | ✅ `highest_seen_ts` — الوقت لا يرجع أبداً |
| مسح بيانات التطبيق | 🟡 يُعاد الضبط (مقبول — لا حل بلا حساب) |
| إعادة التثبيت | 🟡 `device_install_id` جديد (مقبول) |
| **الحل الجذري** | ⭐ **تحويل البيانات عبر السحابة عند التسجيل** — من يسجّل لا يمكنه الإعادة |

#### الطبقة 2 — مع حساب (مستخدم مسجَّل)
```sql
profiles.trial_started_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
profiles.trial_expires_at  TIMESTAMPTZ  GENERATED ... (+ 7 days)
subscriptions.status       TEXT  -- trialing | active | past_due | canceled
```
**✅ مقاومة كاملة لإعادة التثبيت** — لأن `user_id` هو المفتاح، لا الجهاز.

#### الطبقة 3 — سياسة الأوفلاين (مهمة جداً للجزائر)
```
اليوم 0–7:    التجربة نشطة → يعمل كاملاً، بلا إنترنت مطلوب
اليوم 8+:     انتهاء → قفل الكتابة (Soft Lock)
              التحقق محلي من trial_expires_at → لا يحتاج إنترنت ⭐
بلا إنترنت:   سماح إضافي 72 ساعة بعد الانتهاء (لمنع قفل ظالم)
              ثم: «يلزم الاتصال مرة واحدة للتحقق من حالة اشتراكك»
```

### 🎁 توصية إضافية قوية: «تمديد مقابل إجراء»
بدل القفل الفوري، أعطِ المستخدم **طريقاً ثانياً**:
```
+3 أيام إضافية ← مقابل إنشاء حساب (يعطيك بريداً = أصل تسويقي)
+7 أيام إضافية ← مقابل دعوة صديق (رابط إحالة = نمو فيروسي مجاني) ⭐
+7 أيام إضافية ← مقابل تقييم التطبيق/مشاركته
```
> **هذا يحلّ أكبر مشكلة في النموذج الجديد** (موت الانتشار الفيروسي) **مجاناً**.
> **أقترح بقوة تضمينه في MVP** — كلفته ~3 أيام بناء، وعائده نمو مستمر.

## 🔓 ما يحدث عند انتهاء التجربة — قرار مصيري

### ⚠️ المشكلة القانونية والـUX معاً

> **🔴 «القفل الكامل» (Hard Lock) = خطأ فادح لسببين:**
>
> **1. قانوني (القانون 18-07):** للمستخدم **حق الاطلاع على بياناته الشخصية وحق نقلها**. إن قفلتَ تطبيقاً ومنعتَه من رؤية **بياناته المالية هو** → أنت تحجب **بياناته الشخصية** عنه مقابل المال. هذا **خطر قانوني حقيقي** وقد يُعدّ ممارسة تجارية غير عادلة.
>
> **2. تجربة المستخدم:** مستخدم سجّل 200 حركة في 7 أيام، ثم **فقد كل شيء** → سيحذف التطبيق **ويحذّر الناس منه في فيسبوك**. هذا **ضرر تسويقي دائم** لا يُعوَّض.

### ✅ الحل المعتمد: **القفل الجزئي (Soft Lock)** — توصيتي القوية

#### 🟢 يبقى متاحاً **مجاناً وإلى الأبد** بعد انتهاء التجربة
```
✅ عرض كل الحركات والبيانات
✅ كل التقارير والمخططات
✅ تصدير CSV / JSON (حق قانوني — غير قابل للتفاوض)
✅ حذف الحساب وكل البيانات (حق قانوني)
✅ سياسة الخصوصية والشروط
✅ شاشة الاشتراك والدعم
```

#### 🔴 يُقفل حتى الاشتراك
```
🔒 إضافة حركة جديدة
🔒 تعديل أو حذف حركة
🔒 تعديل الميزانيات والحدود
🔒 إنشاء أهداف أو عمليات متكررة
🔒 تصدير PDF
🔒 المزامنة السحابية
🔒 الملفات الإضافية (زوجان/عائلة)
🔒 المرفقات
```

#### 💡 لماذا هذا هو القرار الصحيح تجارياً أيضاً
> **القفل الجزئي أقوى تسويقياً من القفل الكامل.**
> المستخدم يرى بياناته **تنمو أمامه ولا يستطيع إضافة المزيد** → الإحساس بالخسارة (Loss Aversion) **أقوى محفّز للشراء**، بدون غضب وبدون خطر قانوني.

## 🗄️ تحديث هيكل قاعدة البيانات

```sql
-- الباقات (تُدار مركزياً — تغيير الأسعار بلا تحديث التطبيق)
CREATE TABLE plans (
  id              TEXT PRIMARY KEY,        -- 'individual' | 'couple' | 'family'
  name_ar         TEXT NOT NULL,
  name_fr         TEXT NOT NULL,
  max_profiles    SMALLINT NOT NULL,       -- 1 / 2 / 6
  max_devices     SMALLINT NOT NULL,       -- 1 / 2 / 3
  price_monthly   NUMERIC(10,2) NOT NULL,  -- بالدج
  price_yearly    NUMERIC(10,2) NOT NULL,
  is_anchor       BOOLEAN DEFAULT false,   -- المرساة السعرية (العائلة)
  sort_order      SMALLINT NOT NULL,
  is_active       BOOLEAN DEFAULT true
);

-- الاشتراكات
CREATE TABLE subscriptions (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id          UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  plan_id          TEXT NOT NULL REFERENCES plans(id),
  status           TEXT NOT NULL DEFAULT 'trialing'
                   CHECK (status IN ('trialing','active','grace','past_due','canceled')),
  billing_cycle    TEXT NOT NULL CHECK (billing_cycle IN ('monthly','yearly')),
  trial_started_at TIMESTAMPTZ,
  trial_ends_at    TIMESTAMPTZ,
  current_period_start TIMESTAMPTZ,
  current_period_end   TIMESTAMPTZ,
  grace_ends_at    TIMESTAMPTZ,            -- ⭐ 72 ساعة سماح أوفلاين
  activated_by     UUID REFERENCES auth.users(id),  -- الأدمن الذي فعّل
  request_code     TEXT UNIQUE,            -- FL-XXXX-XXXX
  clock_tamper_flag BOOLEAN DEFAULT false,
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- طلبات التفعيل (سجل تدقيق — إلزامي للنزاعات)
CREATE TABLE activation_requests (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id        UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  request_code   TEXT NOT NULL UNIQUE,
  plan_id        TEXT NOT NULL REFERENCES plans(id),
  billing_cycle  TEXT NOT NULL,
  amount_dzd     NUMERIC(10,2) NOT NULL,
  status         TEXT NOT NULL DEFAULT 'pending'
                 CHECK (status IN ('pending','verified','activated','rejected')),
  admin_note     TEXT,                     -- ⚠️ لا بيانات مصرفية هنا أبداً
  requested_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  processed_at   TIMESTAMPTZ,
  processed_by   UUID REFERENCES auth.users(id)
);

-- الملفات الشخصية (لباقات زوجان/العائلة — الطريق أ)
CREATE TABLE profiles_local (
  id          TEXT PRIMARY KEY,            -- UUID محلي
  owner_id    UUID REFERENCES auth.users(id) ON DELETE CASCADE,  -- NULL = بلا حساب
  name        TEXT NOT NULL,
  color_token TEXT NOT NULL,
  emoji       TEXT,
  sort_order  SMALLINT NOT NULL DEFAULT 0,
  is_active   BOOLEAN NOT NULL DEFAULT true,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- كل الحركات والميزانيات تحمل profile_id
```

### 🔒 سياسات RLS (مبدأ)
```sql
-- المستخدم يرى اشتراكه فقط
CREATE POLICY "own_subscription" ON subscriptions
  FOR SELECT USING (auth.uid() = user_id);

-- ⚠️ لا سياسة INSERT/UPDATE للمستخدم أبداً
--    → التفعيل حصري عبر Edge Function بمفتاح Service Role
--    → هذا يمنع المستخدم من تفعيل نفسه بتعديل قاعدة البيانات

-- الأدمن فقط يعدّل
CREATE POLICY "admin_manage" ON subscriptions
  FOR ALL USING (
    EXISTS (SELECT 1 FROM user_roles
            WHERE user_id = auth.uid() AND role = 'admin')
  );
```
