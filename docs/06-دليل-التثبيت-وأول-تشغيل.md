## 0) قبل أن تبدأ: الوقت والمساحة

عندك مسارَان. **ابدأ بالمسار السريع** — يكفي لتشغيل التطبيق على حاسوبك وتجربة المرحلة 1.

| | المسار السريع (تجربة على PC) | المسار الكامل (PC + هاتف APK) |
|---|---|---|
| الأدوات | Git + Flutter + VS Build Tools | + Android Studio + Android SDK |
| الوقت التقريبي | 40–70 دقيقة (أغلبه تنزيل) | ساعتان إلى 3 ساعات |
| المساحة | ≈ 11 GB | ≈ 21 GB |
| متى تحتاجه؟ | **الآن** | حين نبني ملف الهاتف (يمكن تأجيله) |

**متطلبات الجهاز:** Windows 10 أو 11 (64-bit) · ذاكرة 8 GB كحد أدنى (16 GB أفضل بكثير) ·
25 GB مساحة حرة · قرص SSD يجعل البناء أسرع عدة مرات.

## 2) الخطوة 1 — تثبيت Git

1. افتح: **https://git-scm.com/download/win** (يبدأ التنزيل تلقائياً)
2. شغّل الملف المنزَّل واضغط **Next** في كل الشاشات (الإعدادات الافتراضية كافية)
3. في آخر شاشة اضغط **Install** ثم **Finish**

**التحقق** — افتح PowerShell (اضغط `Win` واكتب `powershell` ثم Enter) ونفّذ:

```powershell
git --version
```

✅ **علامة النجاح:** سطر مثل `git version 2.47.1.windows.1`
🔴 إن ظهر `git : The term 'git' is not recognized` → أغلق PowerShell وافتحه من جديد (تحديث PATH يحتاج نافذة جديدة).

## 3) الخطوة 2 — تثبيت Flutter SDK 3.47.5

### 3.1 أنشئ المجلد الذي سيحتوي Flutter

🔴 **قاعدة المكان:** مسار **بلا مسافات وبلا حروف عربية** و**ليس داخل Program Files**
( Program Files يحتاج صلاحيات مدير ويُفسد أدوات البناء).

المكان الموصى به رسمياً: `C:\Users\اسمك\develop`

نفّذ في PowerShell (ينشئ المجلد لك):

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\develop"
```

### 3.2 نزّل Flutter

**الرابط المباشر للإصدار المستقر الحالي (تحقّقنا أنه يعمل):**

```
https://storage.googleapis.com/flutter_infra_release/releases/stable/windows/flutter_windows_3.47.5-stable.zip
```

أو من صفحة الأرشيف الرسمية (اختر **Stable** → **Windows x64**):
**https://docs.flutter.dev/release/archive**

> 🔐 **التحقق من سلامة الملف (اختياري لكنه مطمئن):**
> بصمة SHA-256 الرسمية لهذا الملف:
> `0ccd71931f49c2fbe394b1eeb6d79af3d624058a043ea0d03d34160581624fb8`
> قارنها بأمر واحد بعد التنزيل:
> ```powershell
> Get-FileHash "$env:USERPROFILE\Downloads\flutter_windows_3.47.5-stable.zip" -Algorithm SHA256
> ```

### 3.3 فك الضغط

**بالفأرة:** كليك يمين على ملف zip ← **Extract All** ← اختر `C:\Users\اسمك\develop`

**أو بأمر واحد في PowerShell:**

```powershell
Expand-Archive -Path "$env:USERPROFILE\Downloads\flutter_windows_3.47.5-stable.zip" -DestinationPath "$env:USERPROFILE\develop"
```

**النتيجة المطلوبة:** مجلد `C:\Users\اسمك\develop\flutter` يحتوي بداخله مجلد `bin`.

> ⚠️ انتبه من الخطأ الشائع: أن يصبح لديك `develop\flutter\flutter\bin` (مجلد داخل مجلد).
> إن حدث ذلك انقل محتويات المجلد الداخلي إلى الخارج.

### 3.4 أضف Flutter إلى PATH

**الطريقة الآلية (أمر واحد في PowerShell):**

```powershell
[Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path','User') + ";$env:USERPROFILE\develop\flutter\bin", 'User')
```

**أو الطريقة اليدوية:**
1. `Win + Pause` (أو كليك يمين على **This PC** ← **Properties**)
2. **Advanced system settings** ← تبويب **Advanced** ← **Environment Variables…**
3. في القسم العلوي **User variables for …** اختر **Path** ← **Edit…**
4. **New** ← الصق: `%USERPROFILE%\develop\flutter\bin`
5. **OK** ثلاث مرات

### 3.5 أغلق كل النوافذ وافتح PowerShell من جديد، ثم تحقّق

```powershell
flutter --version
```

✅ **علامة النجاح:**
```
Flutter 3.47.5 • channel stable • https://github.com/flutter/flutter.git
Framework • revision ...
Engine    • revision ...
Tools     • Dart 3.13.4
```

> ⏳ أول تشغيل لأي أمر Flutter يستغرق دقيقة أو دقيقتين (يبني أدواته الداخلية). طبيعي.

## 4) الخطوة 3 — Visual Studio 2022 Build Tools (لنسخة Windows)

🔴 **انتبه:** المطلوب **Visual Studio** وليس **Visual Studio Code** — منتجان مختلفان تماماً.
والمطلوب منه مكوّن واحد فقط: **«Desktop development with C++»**.

1. نزّل (رابط مايكروسوفت المباشر — تحقّقنا أنه يعمل):
   **https://aka.ms/vs/17/release/vs_BuildTools.exe**
   (هذا «أدوات البناء» فقط — أخف بكثير من Visual Studio الكامل ويكفينا)

   > إن فضّلت النسخة الكاملة: **https://visualstudio.microsoft.com/downloads/** ← اختر
   > **Community 2022** (مجانية).

2. شغّل الملف ← في تبويب **Workloads** ضع علامة ✅ على
   **Desktop development with C++**

3. تحقق في الجهة اليمنى (**Installation details**) من وجود هذه المكوّنات
   (تُختار تلقائياً مع الـ workload):
   - MSVC v143 - VS 2022 C++ x64/x86 build tools
   - Windows 11 SDK (أو Windows 10 SDK)
   - C++ CMake tools for Windows

4. اضغط **Install** وانتظر (≈ 7 GB — قد يأخذ 20–40 دقيقة حسب سرعة الإنترنت)

**التحقق:**

```powershell
flutter doctor
```

✅ **علامة النجاح:** `[✓] Visual Studio - develop for Windows (Visual Studio Build Tools 2022 ...)`

## 5) الخطوة 4 — Android Studio (فقط إن أردت بناء APK الآن)

> 💡 **نصيحتي:** أجّل هذه الخطوة. جرّب التطبيق على حاسوبك أولاً (المسار السريع)،
> وحين نصل إلى بناء ملف الهاتف نثبّتها معاً — توفيراً لساعتين و10 GB الآن.

1. نزّل: **https://developer.android.com/studio** ← **Download Android Studio**
2. شغّل المثبّت ← **Next** في كل الشاشات ← **Install** ← **Finish**
3. افتح Android Studio مرة واحدة (قد يطلب تنزيل مكوّنات إضافية ← وافق)
4. من شاشة الترحيب: **More Actions** ← **SDK Manager** ← تأكد من وجود علامة ✅ على:
   - Android SDK Command-line Tools (latest)
   - Android SDK Build-Tools
   - Android SDK Platform (أحدث إصدار معروض)
   ثم **Apply**
5. اقبل التراخيص بأمر واحد:

```powershell
flutter doctor --android-licenses
```

اضغط **y** ثم Enter في كل مرة يسألك (عادةً 7–10 مرات).

✅ **علامة النجاح:** `[✓] Android toolchain - develop for Android devices`

## 7) الخطوة 6 — تشغيل مشروع فلوسنا

### 7.1 ضع المشروع في مكان صحيح

انقل مجلد `falousna` إلى مسار بسيط بلا مسافات ولا حروف عربية، مثلاً:
`C:\Users\اسمك\falousna`

ثم ادخل إليه من PowerShell:

```powershell
cd "$env:USERPROFILE\falousna"
```

**تحقق أنك في المكان الصحيح:**

```powershell
dir
```

يجب أن ترى: `pubspec.yaml` · `lib` · `test` · `assets` · `README_AR.md` · `analysis_options.yaml`

### 7.2 الأوامر السبعة — أمر واحد في كل مرة

| # | الأمر | ماذا يفعل | علامة النجاح |
|---|---|---|---|
| 1 | `flutter create . --platforms=android,windows --org dz.falousna --project-name falousna` | يولّد مجلدات المنصات الناقصة | `All done!` أو `Wrote N files.` |
| 2 | `flutter pub get` | ينزّل المكتبات | `Got dependencies!` |
| 3 | `flutter gen-l10n` | يولّد ملفات الترجمة | بلا أخطاء + يظهر `lib\l10n\app_localizations.dart` |
| 4 | `flutter test` | يشغّل الاختبارات الثمانية | `All tests passed!` |
| 5 | `flutter run -d windows` | **يفتح التطبيق على حاسوبك** | نافذة التطبيق على شاشة «أهلاً بك» |
| 6 | `flutter build apk --release` | يبني ملف الهاتف (يحتاج الخطوة 5) | ملف في `build\app\outputs\flutter-apk\` |
| 7 | `flutter build windows --release` | يبني نسخة PC للتوزيع | مجلد `build\windows\x64\runner\Release\` |

> 🔴 **لا تُضِف `--overwrite` إلى الأمر الأول أبداً** — سيكتب فوق كود المشروع.
> الأمر بدونها **يضيف الناقص فقط** ولا يمسّ ملفاتنا.

**للخروج من التطبيق أثناء `flutter run`:** اضغط `q` في نافذة PowerShell ثم Enter.

## 9) 🔴 تحذير مهم: لا تنفّذ `flutter upgrade` قبل أن أخبرك

### ما الذي تغيّر في Flutter 3.47؟

في **12 أوت 2026** فصلت Google مكتبتَي التصميم **Material** و**Cupertino** عن جسم SDK
وأصبحا حزمتين مستقلتين على pub.dev باسم `material_ui` و`cupertino_ui`
(الحالية: **material_ui 1.3.0** بتاريخ 2026-09-15).

### تحقّقت من كود Flutter نفسه عند الإصدار 3.47.5 (لا من الأخبار):

| السؤال | الجواب المُتحقَّق منه من مصدر SDK |
|---|---|
| هل `package:flutter/material.dart` ما زال موجوداً؟ | ✅ نعم — موجود و**بلا أي وسم إهمال (deprecated)** في 3.47.5 |
| هل `flutter_localizations` ما زال في SDK؟ | ✅ نعم — ويصدّر `GlobalMaterialLocalizations` وغيرها |
| ما إصدار `intl` الذي يطلبه SDK؟ | `intl: ^0.20.3` (لهذا ضبطنا `intl: any` في pubspec — لا تعارض مهما تغيّر SDK) |
| متى يبدأ الإهمال الرسمي؟ | **إصدار نوفمبر 2026 المستقر** → تحذيرات في المحلّل، والكود ما زال يعمل |
| متى يُحذف القديم؟ | **2027** → حينها لا يترجَم الكود القديم |

### قرارنا الموثّق (ولماذا لا نهاجر اليوم)

نبني المراحل 2–5 بالاستيراد الحالي `package:flutter/material.dart` للأسباب التالية:

1. **كل الحزم التي نعتمد عليها ما زالت عليه** (go_router · fl_chart · table_calendar ·
   printing · pdf) — الهجرة الآن تعني شجرة ودجات من مصدرين تحتاج
   `MaterialUiCompatibilityBridge`، أي سطح أخطاء إضافي بلا فائدة اليوم.
2. **الترحيل يمسّ تفويضات الترجمة**: ملفات الترجمة المولَّدة عندنا
   (`AppLocalizations.localizationsDelegates`) تعتمد `flutter_localizations`،
   وبعد الهجرة يجب استبدالها بـ `GlobalMaterialLocalizations.delegates` من `material_ui`.
   تغييرها قبل أن يعمل التطبيق مرة واحدة على جهازك = مخاطرة بعربية وفرنسية الواجهة.
3. **لا شيء مستعجل**: الإصدار 3.47.5 يعمل بلا تحذيرات، والموعد الحقيقي هو 2027.

### ما المطلوب منك تحديداً

- ✅ ثبّت **3.47.5** (رابط §3.2) واعمل عليه طوال المراحل.
- 🔴 **لا تنفّذ `flutter upgrade`** بعد صدور إصدار نوفمبر 2026 حتى أخبرك أن الترحيل تمّ.
- 🟡 إن احتجت الترقية لسبب ما، أخبرني أولاً — الترحيل عندي أمران موثّقان:

```powershell
flutter pub add material_ui
dart fix --apply --code=migrate_design_widgets
```

ثم أُعيد ضبط تفويضات الترجمة (localizationsDelegates) وأعيد تشغيل الاختبارات الثمانية. **مسجّلة كمهمة صيانة مجدولة.**
